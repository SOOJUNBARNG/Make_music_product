## 決定事項

- **モデル: ACE-Step 1.5** (2026-01 公開の後継版。実装時に v1 から切り替え)
  - 構成: XL turbo (DiT 4B, 8 ステップ) + 5Hz LM 1.7B。L4 (24GB) で量子化やオフロードなしで動く構成として公式に推奨されている
  - 1 回の生成で 10 秒〜10 分。music-brief.md の「1 分 30 秒〜3 分」を継ぎ足しなしで作れる
  - ライセンスは MIT で商用利用可 (v1 は Apache 2.0)。旧構成の MusicGen の重みは CC-BY-NC 4.0 (非商用のみ) なので、ゲームに使うなら乗り換えが必要
  - 懸念: カヤグム・琴・二胡などの東アジアの伝統楽器をどこまで再現できるかは、実際に生成して聞くまで分からない
- **GPU: NVIDIA L4 (24GB)** を GCP プロジェクト `jpix-it` で借りる
- 旧構成 (CPU / MusicGen small) は [OLD/](../OLD/) に残している

## 手順

### ① Compute Engine API を有効化

```bash
gcloud services enable compute.googleapis.com --project jpix-it
```

API の有効化自体は無料です。

### ② GPU の割り当てを確認・申請

次の 2 つがどちらも 1 以上必要です。

- `GPUS_ALL_REGIONS`: 全リージョン合計の GPU 数。新しいプロジェクトでは 0 のことが多い
- `NVIDIA_L4_GPUS` (Spot の場合は `PREEMPTIBLE_NVIDIA_L4_GPUS`): リージョンごとの L4 の数

足りない場合は、コンソールの「IAM と管理 → 割り当て」から両方を 1 に増やす申請をします。承認には数分〜数日かかります。

### ③ VM を作成 (割り当ての承認後)

| 項目 | 案 | 理由 |
|---|---|---|
| マシン | `g2-standard-8` (8 vCPU / 32GB / L4×1) | ACE-Step に十分。g2 には L4 が最初から付いている |
| リージョン | us-central1 (第二候補: asia-northeast1 東京) | L4 の在庫が多く料金も安め。一括生成なので距離による遅延は関係ない |
| 料金タイプ | Spot | 通常料金より大幅に安い。途中で止められることがあるが、生成済みの曲を飛ばして再開できる作りにするので相性が良い |
| OS イメージ | Deep Learning VM (PyTorch + CUDA 入り) | GPU ドライバの設定の手間が省ける。具体的なイメージは作成時に最新版を確認する |
| ディスク | 100GB | モデルと生成した音楽の置き場 |

### ④ 費用の安全策

- 予算アラートを設定する (例: 月 50 ドルを超えたらメール通知)
- 生成が終わったら VM を自動で停止する
- 停止中もディスク代 (100GB で月 10 ドル前後) がかかるので、使い終わったら VM ごと削除する

### ⑤ 生成と回収

VM に SSH でコードを送って実行し、出来上がった WAV を手元にコピーします。

## 料金と時間の目安 (概算・未実測)

- g2-standard-8 は通常料金で 1 時間あたり 1 ドル前後、Spot ならその数分の一。作成前にコンソールで実額を確認する
